# MyArena Market — สิ่งที่แพลตฟอร์มทำได้ทั้งหมด

เก็บจากหน้าเว็บจริง (HTML + JS ของ `market.myarenaonline.com`) เมื่อ 22 ต.ค. 2569
ใช้เป็นคลังข้อมูลสำหรับต่อยอดฟีเจอร์ในโปรแกรมของเรา

- คลังไอเทม SF: `https://market.myarenaonline.com/inventory/sf/`
- ตลาดซื้อขาย: `https://market.myarenaonline.com/`
- ล็อกอิน: GG Passport เส้นเดิม (`auth.gg.in.th` appid=1 → appid=84) → คุกกี้ `MyArena_Session`
- ทุกคำสั่ง AJAX เป็น `POST` form-urlencoded และต้องมี `csrf_token` ของหน้านั้น ๆ
- **ใช้ / ขาย / ลบ / คราฟท์ = ย้อนกลับไม่ได้** ต้องยืนยันก่อนทุกครั้ง

## 2) คลังไอเทม — พารามิเตอร์ของหน้า

```
/inventory/sf/?page=N&tab=box|weapon|equip|item&sort=new|old|exp|name|qty&view=u&sell=1
```

| พารามิเตอร์ | ค่า | ความหมาย |
|---|---|---|
| `tab` | (ว่าง) / `box` / `weapon` / `equip` / `item` | ทั้งหมด / กล่องสุ่ม / อาวุธ / อุปกรณ์ / ไอเทม |
| `sort` | `new` (ค่าเริ่มต้น) `old` `exp` `name` `qty` | ได้มาล่าสุด / ได้มาก่อน / ใกล้หมดอายุ / ชื่อ ก-ฮ / จำนวนมากสุด |
| `view` | `u` | ทีละชิ้น (ไม่รวมการ์ดชนิดเดียวกัน) |
| `sell` | `1` | เฉพาะไอเทมที่ตั้งขายได้ |
| `page` | N | แบ่งหน้า + มีช่อง “ไปหน้า” (jump page) |

ข้อมูลบนการ์ดที่เว็บให้มา (เราดึงครบแล้วใน `parse_inventory`):

- `data-inventorydetailid`, `data-itemname`, `data-itemimgurl`, `data-categoryid`
- ป้ายจำนวน `x21` (การ์ดรวมชนิด), `data-islocked` (ล็อกอยู่), แถบสถานะ เช่น `กำลังขาย`
- วันหมดอายุ (`ไม่มีวันหมดอายุ` ได้), “ดูเพิ่ม (N)” (จำนวนซอย/ชิ้นย่อย), ปุ่มใช้แบบ `mktInvConfirmUse` หรือ `mktInvConfirmMultiUse`
- การ์ดที่ยังไม่มีหมวดหมู่ → **ลงขายไม่ได้** จนทีมงานแก้ให้

## 3) การกระทำต่อไอเทม + endpoint จริง

### 3.1 ใช้ไอเทม
```
POST /ajax/inventory_use_preview.php   inventorydetailid, csrf_token[, game_userno]
POST /ajax/inventory_use.php           inventorydetailid, csrf_token[, game_userno][, itemlist[]]
POST /ajax/inventory_multiuse.php      เหมือนกัน — การ์ดรวมชนิด ใช้ได้ครั้งละ 50
```
- preview บอก: ต้องเลือกไอดีเกมหรือไม่ (`need_account` + `accounts[].game_userno`) และมี “กลุ่มรางวัล” ให้เลือกหรือไม่ (`items[].itemtype` 10/60 + `choices[].itemsrl` + `needed_count`)
- กล่องสุ่ม/ไอเทมที่มีรางวัลให้เลือก **ต้องส่ง `itemlist[]` เอง** — ถ้าไม่ส่งเว็บจะไม่ให้ใช้ (ของเราเลือก “ข้าม” อย่างปลอดภัย)
- endpoint ดูจาก **ปุ่มบนการ์ด** ไม่ใช่ป้ายจำนวน: ปุ่ม `mktInvConfirmMultiUse` → `multiuse`,
  ปุ่ม `mktInvConfirmUse` ธรรมดา → `use` ทีละชิ้น (การ์ดที่มีป้าย ×N ก็เป็นแบบนี้ได้ —
  ยิง `multiuse` ใส่รหัสของการ์ดแบบนี้เว็บตอบ `This SerialCode cannot used`)
- การ์ดปุ่ม `Use` ใช้ได้ **1 ชิ้นต่อคำขอ** แล้ว `inventorydetailid` เดิมหายไป —
  ชิ้นที่เหลือไปอยู่รหัสใหม่ ⇒ ต้อง GET คลังใหม่ก่อนยิงชิ้นถัดไป (ทดสอบจริง 23/10/2569:
  การ์ด 2 ชิ้น → 2 คำขอ + อ่านคลังใหม่ 1 ครั้ง → ครบ 2 ชิ้น)

### 3.2 เปิดกล่อง
```
POST /ajax/inventory_open.php       inventorydetailid, csrf_token
POST /ajax/inventory_multiopen.php  itemcenterid, count (สูงสุด 50/ครั้ง), csrf_token
```
- `multiopen` ฝั่งเว็บวนยิงทีละ 50 จนครบจำนวนที่ขอ (ตั้งได้ 1–10,000 กล่อง), มี progress bar + ปุ่มหยุด
- กล่องที่เปิดไม่สำเร็จถูก rollback ทั้งกล่อง (ของยังอยู่) — response มี `items`, จำนวนที่เปิดได้, เหตุผลที่พลาด
- ฝั่งเว็บมีอนิเมชัน “เขย่ากล่อง” ก่อนโชว์ผล (แค่เอฟเฟกต์ ผลถูกสุ่มที่เซิร์ฟเวอร์แล้ว)

### 3.3 คราฟท์ (4 ขั้น)
```
POST /ajax/inventory_craft_get_available.php  inventorydetailid, csrf_token
POST /ajax/inventory_craft_process.php        inventorydetailid, craft_id, reward_id, csrf_token
```
- ขั้นที่ 1 เลือกสูตร → 2 วัตถุดิบที่ต้องใช้/มีพอ → 3 เลือกรางวัล → 4 ผลลัพธ์
- response บอก `Items` (ได้อะไร), `skipped` (ข้ามเพราะเงื่อนไข), `materials_used` (วัตถุดิบที่ใช้)
- บางสูตรเป็น “โหมดภายใน” (`IsInternalMode=1`) ปุ่มจะเปลี่ยนเป็น “รับของ”

### 3.4 ขายไอเทม
```
GET  /ajax/mymarket_get_referenceprice.php?itemcenterid=&inventorydetailid=
POST /ajax/seller_check_spend.php        csrf_token
POST /ajax/inventory_accept_seller_agreement.php  accept_checkbox=1, csrf_token
POST /ajax/inventory_sell.php            inventorydetailid, price, gamecode=sf, csrf_token
     (+ การขายหลายชิ้น: ตอบ `nextinventorydetailid` แล้วยิงต่อทีละชิ้น)
```
กติกาที่เว็บบังคับ (ดึงมาจาก JS จริง):
- ราคา **10–30,000 บาท** และต้องเป็น **จำนวนเต็ม**
- จำนวนที่ลงขายต่อครั้ง **สูงสุด 50 ชิ้น** (ปุ่ม “สูงสุด” เติมให้)
- **ค่าธรรมเนียม 10%** — การ์ดโชว์ “ค่าธรรมเนียม (10%)” และ “ร้านค้าจะได้รับ”
- Suggested price เติมให้อัตโนมัติจากราคาอ้างอิงตลาด + โชว์ช่วงราคาต่ำสุด–สูงสุดที่ตั้งอยู่ตอนนี้ และจำนวนที่ลงได้
- มี “จะประกาศขายถึงวันที่” (end date) มากับ preview
- ต้องยอมรับเงื่อนไขร้านค้า + ตั้งชื่อร้าน + มีกระเป๋าก่อน
- ขายหลายชิ้น: เว็บยิง `inventory_sell.php` ต่อเนื่องตาม `nextinventorydetailid` (ของเรา: ยังไม่ทำ)

### 3.5 จัดการประกาศ / ไอเทม
```
POST /ajax/inventory_cancel_selling.php  inventorydetailid, csrf_token   ยกเลิกประกาศขาย
POST /ajax/inventory_lock.php            inventorydetailid, islock=Y|N    ล็อก/ปลดล็อก
POST /ajax/inventory_delete.php          inventorydetailid, csrf_token   ลบ 1 ชิ้น
POST /ajax/inventory_deleteall.php       inventorydetailid, csrf_token   ลบทั้งการ์ด (ทุกชิ้น)
POST /ajax/inventory_mapping_unlink.php  myappid, refid, csrf_token      ยกเลิกผูกไอดีเกม
```
- ปุ่มล็อกอยู่มุมรูปการ์ด (`data-islocked`), ไอเทมที่ล็อก/กำลังขายห้ามใช้
- “ยกเลิกผูกไอดีเกม” ทำได้เฉพาะเมื่อเหลือไอดีผูกอยู่อย่างน้อย 2 (เซิร์ฟเวอร์เช็คให้)

### 3.6 ชื่อร้าน / ชื่อที่แสดง
```
POST /ajax/inventory_verify_displayname.php   displayname (3–30 ตัวอักษร), csrf_token
POST /ajax/inventory_update_displayname.php   displayname, csrf_token
```
- ต้องยืนยันชื่อก่อน **ซื้อหรือขาย**; ตั้งได้ **ครั้งเดียว** แก้ไม่ได้ภายหลัง
- มี checkbox ยืนยัน + ตัวอย่างชื่อ + คำเตือนถ้าใช้ชื่อ default

### 3.7 กระเป๋า / ยอดใช้จ่าย
- `seller_check_spend.php`: เช็คยอดใช้จ่ายเดือนนี้ (แตะระบบ BILL3DB, cache ฝั่งเซิร์ฟเวอร์ 5 นาที, บอกว่าผลมาจาก cache หรือสด)
- `market_wallet_verify.php?return_to=…`: ผูก/ยืนยันกระเป๋าตังค์รับเงิน
- หน้าแรกตลาดโชว์ “จัดการกระเป๋าตังค์”, “ยังไม่เชื่อมต่อ”, ระดับร้าน VIP

## 4) ระบบตลาด (ฝั่งซื้อขาย)

หน้าแรก `market.myarenaonline.com` มี:
- **สินค้าแนะนำจากร้านแนะนำ**, **เทรนด์สินค้าช่วงนี้**, **อาวุธมาแรง**, **สินค้าลงขายล่าสุด** (พร้อมป้าย `ใหม่` และจำนวนร้านค้าที่ขาย)
- **ค้นหา** (ค้นหาล่าสุด / ล้างทั้งหมด / ผลการค้นหาเบื้องต้น / ดูทั้งหมด)
- **สินค้าที่คุณเพิ่งดู**, **สินค้าที่คุณสนใจ**, **ระดับร้านค้า VIP**
- **MyArenaPay** (TrueMoney / QR) — จ่ายแล้ว **ไอเทมเข้าคลังอัตโนมัติ**
- **แจ้งปัญหาจากหน้าซื้อ** ให้ทีมงานติดตาม
- ปุ่ม **เริ่มขาย** → เลือกไอเทมจากคลัง → ตั้งราคาเอง (ค่าธรรมเนียม 10%) → เงินเข้า Wallet
- หน้าร้านสาธารณะ `/shop/<ชื่อร้าน>/`, แชทกับร้าน, ข้อความ

## 5) ข้อจำกัด/รายละเอียดที่เจอจริง (สำคัญเวลาทำ automation)

1. `csrf_token` เปลี่ยนตามหน้า — ต้องอ่านจาก HTML ทุกครั้งที่โหลดคลัง
2. 1 บัญชีผูกได้หลาย “ไอดีเกม” (ช่องที่ 1, 2, …) — ใช้ไอเทมบางชนิดต้องเลือก `game_userno`
3. ป้าย ×N บนการ์ด **ไม่บอกว่าใช้ endpoint ไหน** — ต้องอ่าน `onclick` ของปุ่ม: `mktInvConfirmMultiUse` → `inventory_multiuse` (ครั้งละ ≤50), `mktInvConfirmUse` → `inventory_use` ทีละชิ้น (ของ 48 ชิ้น 6 การ์ด = 6 การ์ดปุ่ม `Use` ทั้งหมด — ยิง `multiuse` แล้วพลาดทั้งชุด) และหลังใช้ 1 ชิ้นรหัสการ์ดเปลี่ยน ต้องอ่านคลังใหม่ก่อนใช้ชิ้นต่อไป
4. `multiuse` ใช้ได้ครั้งละ **50** — ของ 120 ชิ้น = 3 คำขอ
5. ราคาขาย 10–30,000 บาท จำนวนเต็ม, ลงขายได้ครั้งละ ≤ 50 ชิ้น, หัก 10%
6. ไอเทมไม่มีหมวดหมู่ = ลงขายไม่ได้; ไอเทมล็อก/กำลังขาย = ใช้ไม่ได้
7. เปิดกล่องหลายกล่อง: ≤ 50 ต่อคำขอ, เป้าหมายสูงสุด 10,000, หยุดกลางทางได้, กล่องที่พังถูกคืน
8. ใช้/ลบ/ขาย เป็นการกระทำถาวร — ห้าม retry POST อัตโนมัติ (ของอาจออกซ้ำ)

## 6) ฟีเจอร์ที่เราเอามาต่อยอดได้ (เรียงตามความคุ้ม)

| # | ฟีเจอร์ | ใช้ endpoint | สถานะในโปรแกรม |
|---|---|---|---|
| 1 | ใช้ไอเทมทีละหลายชิ้นในคลิกเดียว (รวมการ์ด xN) | `use_preview` + `use` / `multiuse` | ✅ ทำแล้ว |
| 2 | แสดงจำนวน/สถานะ/ล็อก/วันหมดอายุ บนการ์ด | `parse_inventory` | ✅ ทำแล้ว |
| 3 | เปิดกล่องทีละมาก ๆ (1–10,000) พร้อม progress + หยุด | `multiopen` | ✅ ทำแล้ว |
| 4 | คราฟท์ (เลือกสูตร/ตรวจวัตถุดิบ/เลือกรางวัล/ยืนยัน) | `craft_get_available` + `craft_process` | ✅ ทำแล้ว |
| 5 | ลงขายครั้งละหลายชิ้น (≤50) ด้วยราคาแนะนำจากตลาด | `get_referenceprice` + `sell` | ✅ ทำแล้ว |
| 6 | ยกเลิกประกาศขาย / ลบทั้งการ์ด / ล็อก–ปลดล็อก แบบกลุ่ม | `cancel_selling`, `deleteall`, `lock` | ✅ ทำแล้ว |
| 7 | ตั้งชื่อร้าน + ยอมรับเงื่อนไข + เช็คกระเป๋า (onboarding ร้านค้า) | `verify/update_displayname`, `accept_seller_agreement`, wallet | ✅ ทำแล้ว |
| 8 | เช็คยอดใช้จ่ายเดือนนี้ / ระดับ VIP | `seller_check_spend`, `/vip/` | ✅ เช็คยอด + เปิดหน้า VIP |
| 9 | เตือนไอเทมใกล้หมดอายุ + กรองเฉพาะใกล้หมดอายุ | `?sort=exp` | ✅ ทำแล้ว |
| 10 | ประวัติการใช้งานในโปรแกรม (อ่านอย่างเดียว) + สรุปยอดขาย/รายได้รวมด้านบนตาราง | `/inventory/history/` | ✅ ทำแล้ว |
| 11 | ดึงคลังหลายบัญชีพร้อมกัน (อุ่นเซสชันล่วงหน้า) | `fetch_pages` (6 หน้าพร้อมกัน) | ✅ ทำแล้ว |

> หมายเหตุด้านความปลอดภัย: ทุกฟีเจอร์ที่เป็นการกระทำถาวร (ใช้/ขาย/ลบ/คราฟท์/เปิดกล่อง)
> ต้องยืนยันจากผู้ใช้ก่อนเริ่ม และต้องไม่ retry คำสั่งที่พลาดโดยอัตโนมัติ
